# Phase 113 counting references and independent implementations

The official [STAR Voting Technical Specifications v1.3](https://assets.nationbuilder.com/unifiedprimary/pages/501/attachments/original/1734730674/STAR_Voting_Technical_Specifications_V1.3.pdf?1734730674=), published December 20, 2024, identifies Allocated Score in its technical Appendix D (PDF pages 13-14; the document also reuses the Appendix D heading later). Downloaded artifact: 1,823,160 bytes, 21 pages, SHA-256 `84cb769f1a64aa3251c1b4e7fc30c42f93fb4990610bcdcc4ddc44e0f0c634a8`. The initial command-line request returned 403; ordinary browser headers retrieved the official asset. The reference stays in local test scratch, outside release staging.

Reference procedure: select the highest remaining score, sort voters by their remaining contribution to that selected candidate, consume contribution bands toward a quota, and handle a boundary band with a common fraction. Its normalization by five is immaterial to score ordering. We independently implemented these mathematical operations with exact rational arithmetic and separated original represented weight from remaining fraction. No PDF or reference source code was copied into the MIT application or tests; the PDF does not identify a software license for its embedded sample. No reference library is a runtime dependency.

The approved platform policies additionally freeze quota as original informative voting weight divided by requested K, exclude zero-weight/abstention/all-zero ballots from that allocation denominator, include zero-contribution bands when needed, and stop on exhausted positive support. Strict ties use the already committed candidate priority. The literal unit-voter oracle is independently authored and handles these policies explicitly. Allocation changes influence within this proposal only; member shares and delegation rights never change.

`starvote==2.1.5`, Larry Hastings copyright 2023, is installed only into isolated test scratch. Its bundled LICENSE grants MIT permission. Existing single STAR and Bloc STAR comparisons use its public API. Its Allocated Score routine is **not** the full W6 oracle: review found later-round allocation compares group headcounts rather than their remaining mass and skips zero-contribution nonsupporters. Those choices differ from the approved exact contract. The PDF's floating-point sample also has a strict-cumulative threshold corner; our explicit equal-band mass contract supplies the boundary rule. No code from either source was reused.

Concrete zero-contribution policy fixture: 30 voters rate only A5 and 20 only B5 with K=2. Quota is 25. A consumes 25 from the first group uniformly, retaining fraction 1/6 for each. B then consumes its 20 positive-support weight plus the first group's remaining five weight at contribution zero. This is preserved and disclosed as the published-order/platform contract, rather than replacing it with a positive-support-only variant.

The independent 60/40, five-seat illustration yields three A-supported and two B-supported selections; the four nonproportional methods can select five A options. This describes expressed support and voting weight, not demographic representation guarantees.
